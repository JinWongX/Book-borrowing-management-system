# 企业图书借阅管理系统 - 产品需求文档（PRD）

> 版本：v1.0  
> 日期：2026-07-31  
> 状态：已落地实现

---

## 1. 项目背景与目标

### 1.1 背景

公司员工图书角目前使用纸质登记本管理 500–1000 册图书，存在以下痛点：

- **登记遗漏**：手工登记容易漏记、错记，借阅历史难以追溯。
- **库存不透明**：员工无法实时查询图书在库状态，导致重复询问或白跑一趟。
- **逾期难追踪**：到期与逾期依赖人工记忆，催还效率低。
- **统计困难**：热门图书、部门借阅情况无法量化，采购与管理决策缺乏数据支撑。

### 1.2 目标

建设一套轻量级企业图书借阅管理系统，实现图书信息、分类、检索、借阅申请、审核、借还登记、逾期提醒、统计报表等全流程线上化，提升图书管理效率与员工借阅体验。

### 1.3 范围

- **前端**：基于 React + Ant Design 的 Web 管理端，面向员工、图书管理员、系统管理员。
- **后端**：基于 FastAPI + SQLAlchemy + SQLite 的 RESTful API 服务。
- **数据**：SQLite 单文件数据库，适用于中小规模企业内部部署。

## 3. 功能需求

### 3.1 用户认证与 RBAC

- **FR-AUTH-01**：系统提供账号密码登录，登录成功后后端返回 JWT Token。
- **FR-AUTH-02**：前端将 Token 持久化至 `localStorage`，并在后续请求中通过 `Authorization: Bearer <token>` 携带。
- **FR-AUTH-03**：系统根据登录用户角色动态渲染侧边菜单与页面访问权限。
- **FR-AUTH-04**：Token 过期或鉴权失败时，前端自动跳转登录页。
- **FR-AUTH-05**：内置三个种子账号：`employee` / `librarian` / `admin`，初始密码通过环境变量 `INITIAL_PASSWORD_*` 配置；未配置时系统生成随机强密码并输出到控制台，首次部署后必须修改。

### 3.2 图书分类管理

- **FR-CAT-01**：支持多级分类树，例如 `技术 > 编程语言 > Java`。
- **FR-CAT-02**：支持新增、编辑、删除分类节点。
- **FR-CAT-03**：删除分类时校验：若存在子分类或关联图书，则禁止删除。
- **FR-CAT-04**：编辑分类父节点时禁止形成循环依赖（不能设置自己为父节点、不能移动到子节点下）。

### 3.3 图书信息管理

- **FR-BOOK-01**：维护图书基本信息：书名、作者、ISBN、出版社、分类、库存、上架位置、封面图。
- **FR-BOOK-02**：新增/编辑图书时校验 ISBN 唯一性。
- **FR-BOOK-03**：支持封面图片本地上传，上传后返回可访问 URL。
- **FR-BOOK-04**：删除图书为物理删除；当前系统未校验在借记录，需管理员谨慎操作。
- **FR-BOOK-05**：图书列表支持分页展示，默认每页 10 条。

### 3.4 图书检索

- **FR-SEARCH-01**：支持按关键词对书名、作者、ISBN 进行模糊搜索。
- **FR-SEARCH-02**：支持按分类筛选，筛选时包含该分类下所有子分类的图书。
- **FR-SEARCH-03**：搜索结果支持分页。

### 3.5 借阅申请

- **FR-BORROW-01**：员工在图书详情页选择预计归还日期后发起借阅申请。
- **FR-BORROW-02**：仅当图书库存大于 0 时允许申请；库存不足给出明确提示。
- **FR-BORROW-03**：预计归还日期必须晚于当前时间。
- **FR-BORROW-04**：申请生成后状态为 `pending`（待审核）。
- **FR-BORROW-05**：员工可在“我的借阅”中查看全部申请记录及当前状态。

### 3.6 借阅审核

- **FR-AUDIT-01**：图书管理员在“借阅审核”页面查看所有待审核申请。
- **FR-AUDIT-02**：管理员可通过申请，状态变更为 `approved`（已批准）。
- **FR-AUDIT-03**：管理员可拒绝申请，填写拒绝理由，状态变更为 `rejected`（已拒绝），员工可见拒绝理由。

### 3.7 借还登记

- **FR-LEND-01**：对于已批准申请，管理员进行借出登记，实际库存减 1，状态变更为 `borrowed`（借阅中），记录实际借出时间。
- **FR-LEND-02**：借出登记时再次校验库存，库存不足则失败。
- **FR-RETURN-01**：对于借阅中记录，管理员进行归还登记，实际库存加 1，状态变更为 `returned`（已归还），记录实际归还时间。
- **FR-RETURN-02**：前端借还登记页面支持扫码或手动输入借阅单号（UI 预留）。

### 3.8 逾期提醒

- **FR-OVERDUE-01**：系统启动后台线程，每天扫描一次处于 `borrowed` 状态的借阅单。
- **FR-OVERDUE-02**：距离预计归还日 3 天及以内生成站内提醒消息。
- **FR-OVERDUE-03**：逾期后每天生成一条站内提醒消息。
- **FR-OVERDUE-04**：同一天内同一借阅单仅生成一条提醒，避免重复。
- **FR-OVERDUE-05**：管理员可在“逾期列表”查看所有逾期未还的借阅记录。
- **FR-OVERDUE-06**：员工可在“消息中心”查看提醒并标记已读。

### 3.9 统计报表与导出

- **FR-STAT-01**：按图书维度统计借阅次数。
- **FR-STAT-02**：按分类维度统计借阅次数。
- **FR-STAT-03**：按部门维度统计借阅次数。
- **FR-STAT-04**：按个人维度统计借阅次数。
- **FR-STAT-05**：展示热门图书 Top20。
- **FR-STAT-06**：支持将统计结果导出为 Excel（.xlsx）或 CSV 格式。

## 4. 业务流程

### 4.1 借阅申请流程

```
员工登录 → 浏览/搜索图书 → 选择图书与预计归还日期 → 提交申请
                                          ↓
                              [库存>0 且 归还日期未来]
                                          ↓
                              生成待审核借阅单（pending）
```

### 4.2 借阅审核流程

```
图书管理员登录 → 进入借阅审核 → 查看 pending 申请列表
                          ↓
            ┌─────────────┼─────────────┐
            ↓             ↓             ↓
         通过          拒绝          关闭
            ↓             ↓
      approved      rejected（附理由）
            ↓
     等待借出登记
```

### 4.3 借还登记流程

```
图书管理员登录 → 进入借还登记
                          ↓
            ┌─────────────┴─────────────┐
            ↓                           ↓
      借出登记                      归还登记
   （选择 approved 记录）         （选择 borrowed 记录）
            ↓                           ↓
      库存 - 1                    库存 + 1
      actual_lend_date = now      actual_return_date = now
      status = borrowed           status = returned
```

## 5. 用户场景

### 场景 1：新员工借阅技术书籍

**角色**：员工小张  
**背景**：小张入职技术部，需要借阅一本 Java 类图书。  
**流程**：

1. 小张使用账号 `employee` 登录系统。
2. 在“图书检索”页面输入关键词“Java”。
3. 查看《Effective Java》详情，确认库存为 3。
4. 选择预计归还日期为 30 天后，提交借阅申请。
5. 系统在“我的借阅”中生成一条状态为“待审核”的记录。
6. 管理员审核通过后完成借出登记，小张收到消息提醒，前往图书角取书。

**价值**：员工可自助查询与申请，减少人工沟通成本。

### 场景 2：图书管理员处理批量借还

**角色**：图书管理员李姐  
**背景**：每周五是固定借还书日，李姐需要集中处理。  
**流程**：

1. 李姐使用账号 `librarian` 登录系统。
2. 进入“借阅审核”，批量通过本周员工提交的申请。
3. 进入“借还登记”，对每位员工的已批准申请执行借出登记，系统自动扣减库存。
4. 对于到期的图书，执行归还登记，系统自动恢复库存。
5. 在“逾期列表”中查看逾期未还的借阅记录，及时催还。

**价值**：管理员在一个页面完成审核与借还，库存与状态自动联动。

### 场景 3：部门借阅情况统计与采购决策

**角色**：系统管理员王工  
**背景**：公司计划扩充技术类图书采购，需要数据支撑。  
**流程**：

1. 王工使用账号 `admin` 登录系统。
2. 进入“统计报表”页面，查看按分类统计的借阅次数。
3. 发现“技术 > 编程语言 > Java”分类借阅量最高，且 Top20 中 Java 图书占比超过 40%。
4. 选择“分类统计”导出 Excel，用于采购会议汇报。

**价值**：用数据驱动图书采购与预算分配。

## 6. 非功能需求

### 6.1 性能需求

- **NFR-PERF-01**：图书检索接口在 1000 册图书规模下响应时间不超过 500ms。
- **NFR-PERF-02**：登录接口响应时间不超过 300ms。
- **NFR-PERF-03**：统计报表页面首次加载不超过 2s。

### 6.2 安全需求

- **NFR-SEC-01**：用户密码使用 bcrypt 加盐哈希存储，禁止明文保存。
- **NFR-SEC-02**：接口使用 JWT 鉴权，Token 默认有效期 24 小时。
- **NFR-SEC-03**：后端对所有接口统一进行权限校验，防止越权访问。
- **NFR-SEC-04**：生产环境需替换默认 `SECRET_KEY`，并通过 `.env` 文件管理敏感配置。

### 6.3 可用性需求

- **NFR-AVA-01**：系统支持本地一键启动，便于演示与测试。
- **NFR-AVA-02**：后端提供 `/health` 健康检查接口。
- **NFR-AVA-03**：前端在 Token 失效或网络异常时给出明确提示并引导重新登录。

### 6.4 可维护性需求

- **NFR-MAINT-01**：前后端代码按模块分层，路由/模型/模式/服务职责清晰。
- **NFR-MAINT-02**：后端提供统一响应格式 `{code, message, data}` 与全局异常处理。
- **NFR-MAINT-03**：数据库初始化脚本自动创建表、迁移缺失字段并注入种子数据。

### 6.5 兼容性需求

- **NFR-COMP-01**：前端兼容 Chrome、Edge 等现代浏览器。
- **NFR-COMP-02**：后端基于 Python 3.10+ 运行，SQLite 无需额外数据库服务。

### 6.6 部署需求

- **NFR-DEP-01**：后端使用 Uvicorn 运行，默认端口 8000。
- **NFR-DEP-02**：前端开发服务器默认端口 5173，构建产物可放置于任意静态服务器。
- **NFR-DEP-03**：跨域配置默认允许 `localhost:3000` 与 `localhost:5173`。
